Steward acceptance condition

ACCEPTED PILOT-CTX-SS-001 is accepted on the basis that every engagement is integrated with the Mesh and DIM and is continually challenged for antifragile learning from Home and all nine Element entry pages.

Meaning: the system does not merely ask whether work passed. It asks what could make it fail, appear complete while wrong, become brittle under changed conditions, or produce harm through hidden dependencies. Expected-versus-observed divergence becomes learning evidence, not an exception to hide.

Authority boundary: this acceptance authorises the interface challenge layer and pilot progression only. V7 Activate remains HOLD. Odoo/N8N/runtime mutation, Benefit declaration, Pattern/Asset/canon promotion and PPV movement remain separately held.

Mesh ↔ DIM challenge mapping

1. SignalState the claim, expected condition or operating hypothesis.
2. InterpretationInvert it: identify how it could be wrong, incomplete, gamed or context-bound.
3. StructuringDefine the smallest stress test, counterexample and evidence needed.
4. ValidationChallenge identity, authority, causal logic, dependencies, risk and falsifiability.
5. ActionRun only the bounded authorised test; gates remain fail-closed.
6. ObservationRecord expected versus observed conditions and defects.
7. LearningIdentify structural root cause, not only symptom, and the smallest resilience-increasing adaptation.
8. Asset ConversionHold qualification until repeated evidenced use and separate authority.
9. FeedbackReturn receipts, contradictions and learning as new Signals through RULE.

Continuous challenge rule

1. HypothesisWhat do we expect to be true, for whom, in which Context, and why?
2. InversionWhat would cause failure, hidden brittleness, false completion or adverse selection?
3. StressWhat smallest counterexample, boundary test or hostile condition can expose the weakness?
4. ObserveWhat actually happened, compared with the stated expectation?
5. Root causeWhich structural assumption, dependency, incentive, interface or method step produced the outcome?
6. AdaptWhat smallest change improves resilience without adding unnecessary Form?
7. Re-runDoes the change survive the same test and an adjacent Context?
8. LearnFile the evidence, implication and next valid step; recurring breakdowns become DIM learning candidates.
9. Qualify carefullyReuse evidence may support a future Method, Pattern or Asset candidate; qualification remains held to evidence and Steward authority.

DIM learning triggers

  • expected versus observed divergence
  • the same breakdown class recurs on a second engagement or context
  • a contradiction, missing evidence or authority ambiguity survives validation
  • a gate is bypassed, falsely passed or produces an unauthorised action
  • a Benefit, Pattern, Asset, canon or PPV claim lacks its written realisation or qualification condition
  • a route, Context crossing, owner handoff or runtime assumption fails or requires reconstruction

RULE recursion: Read evidence and receipts → Underline the consequential challenge → Let the Steward rule where authority is required → Execute only the bounded authorised move with receipt. Each receipt re-enters as Read evidence.

Method-learning records support observation, root cause, implication, next valid step, evidence anchor and review status. This interface exposes that discipline; it does not create register records.
