Does not own: Method how-to logic, Service purpose, Benefit-realisation authority or canonical promotion.

Instance definitions

1. Structural patterns

Purpose

Reusable arrangements of roles, objects, layers and relationships.

Design attributes

architecture, hierarchy, network, modularity

Kinematics

configuration-led; stable topology; variable scale

Required integrations

Context & Membrane; Service/Method/Pattern or equivalent substantive relationships; Mesh gates; Benefit & Asset mapping; Work Object continuity; Agent/runtime route where applicable.

Variations

Vary by Context level, lifecycle state, scale, authority, design PPV, operational PPV, risk and evidence maturity.

MECE test

Own only the category responsibility; reference adjacent elements without duplicating their substance.

Strategy mapping

Select the specific Strategy this instance advances and state the causal contribution, assumptions and trade-offs.

Asset mapping

Select the persistent Asset class protected, created, compounded or converted by this instance.

SMART Benefit

Achievable: confirm capability, authority, dependencies and constraints. Relevant: link the instance to a named Strategy and intended Asset class. Time-bound: define observation date, review cadence and realisation decision point.

Nine-verb and Mesh alignment

VerbElement-specific action across the taxonomyPrimary Mesh position
OrientIdentify the Context, recurring structure or value-bearing result, then determine whether the subject is a Pattern candidate, an Asset candidate, both, or neither. State the problem, beneficiary, evidence boundary and intended reuse.Signal
CanonicaliseResolve names, category, scope, lineage and reference definitions without implying Pattern qualification or Asset status. Link authoritative sources and record conflicts.Interpretation
StructureDefine the candidate's attributes, variations, kinematics, relationships, recurrence criteria, reuse conditions, qualification thresholds and failure boundaries.Structuring
AssureChallenge recurrence, usefulness, transferability, evidence quality, harmful variation, ownership boundaries and false-positive risks. Distinguish repeated coincidence from an evidenced reusable Pattern.Validation
NavigateSelect the permitted route: observe further, test in another Context, retain as candidate, reject, hold, qualify for controlled reuse, or refer an Asset decision to the authorised owner.Action
ComposeAssemble the bounded Pattern or Asset package with purpose, Context, inputs, outputs, Methods, controls, evidence, variants, interfaces, Benefit hypotheses and return route.Observation
ActivateRelease only the authorised use within the declared Context, constraints and rollback boundary. Activation does not itself qualify the Pattern, realise the Benefit or promote the Asset.Learning
TransformUse observed performance, exceptions, inversion and cross-Context evidence to adapt, split, merge, retire or strengthen the candidate while preserving lineage and authority.Asset Conversion
ProjectShow where the qualified Pattern may be reused and where the persistent Asset may compound, including Strategy contribution, SMART Benefit conditions, evidence needs, Context limits and future review points.Feedback

Context-specific Strategy → Benefit → Asset contract

1. Context

Select the exact ecosystem, enterprise, client, partner, program, project, market, platform or design Context.

2. Strategy

Select the named Strategy and state the causal contribution expected from this instance.

3. Instance

Select one taxonomy category and its permitted variation.

4. SMART Benefit

Name beneficiary, baseline, target, indicator, evidence source, attribution rule and decision date.

5. Asset

Name the persistent Asset class expected if the Benefit is evidenced and qualified.

6. PPV and authority

Record design PPV and operational PPV separately; progression remains evidence- and authority-gated.

Acceptance tests

  1. All nine design-instance categories are distinct and collectively cover the element design space.
  2. Each category defines purpose, attributes, variations, kinematics, integrations and MECE boundary.
  3. Each category can be selected for a specific Context.
  4. Each selected instance maps to a named Strategy, SMART Benefit and Asset class.
  5. Nine verbs and all Mesh stages are element-specific, not generic outcome text.
  6. No operational record detail is fabricated or duplicated from Odoo.
  7. No browser preview, network access, remote dependency, iframe or permission prompt is required.
