Nine verbs applied

Orient

Identify beneficiary, intended change, baseline and strategic relevance.

Canonicalise

Resolve Benefit identity and prevent duplicate or overlapping definitions.

Structure

Bind measure, target, evidence, attribution, Service, Work Object and Asset hypothesis.

Assure

Test MECE coverage, causality, confidence and authority of claims.

Navigate

Trace from Service and Work Object to Benefit evidence and Asset effect.

Compose

Combine Benefits into a portfolio without double counting.

Activate

Approve measurement or qualification action, not the realised claim itself.

Transform

Update Benefits or Asset hypotheses from observations and counterfactuals.

Project

Show expected, observed, realised and qualified states distinctly.

Mesh integration

Entry

A signal or governed need enters with identity, Context and source.

Validation

Evidence, MECE, authority, PPV and readiness are tested.

Action

Only an authorised expression may change governed work.

Observation

Effects, exceptions and source receipts are recorded.

Asset conversion

Reusable value is proposed only after repeated evidence.

Feedback

Learning returns to the owning element and current Work Object.

Cross-element MECE ownership

Owns

Benefit definition, beneficiary, measure, evidence, attribution and realised-state claim; Asset effect and qualification hypothesis.

Does not own

Service scope, Method procedure, Pattern admission, canonical authority, Work Object execution or runtime configuration.

Integration contract

Every relationship names the owning element, referenced object, evidence route and authority state; shared relationships are explicit, never duplicate ownership.

Design-instance inventory

Enough instance identity and relationships are shown for design, integration and stress testing. Mutable operational fields, transactions, performance and runtime configuration remain in Odoo/N8N.
