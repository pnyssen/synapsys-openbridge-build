Nine verbs applied to Services

Orient

Identify the need, Context, beneficiary, current Service coverage and controlling Work Object.

Canonicalise

Resolve the Service code, name, boundary, terminology and authoritative basis; storage alone is not canon.

Structure

Connect Service to Context, Method, Pattern, canonical basis, Work Object, expected Benefit and potential Asset effect.

Assure

Test MECE coverage, evidence, authority, PPV, relationship completeness and inversion failure modes.

Navigate

Locate the correct Service and its current design, evidence, Odoo reference and queue position.

Compose

Combine complementary Services and dependencies without duplicating scope or Benefits.

Activate

Release one authorised Service expression into a Work Object; all operational mutation remains D007-gated.

Transform

Use observed evidence and A/B learning to refine, split, retire or recombine Services.

Project

Display the current read-only catalogue, freshness, gaps and source boundaries without claiming operational truth.

Mesh integration and kinematics

Entry
Need, opportunity, obligation or capability gap enters as a Signal.
Validation
Identity, MECE, relationships, evidence, PPV and authority are tested.
Action
An authorised Service expression enters a Work Object.
Observation
Outcomes, exceptions and attribution are recorded.
Asset conversion
Repeated evidenced value may enter Asset Qualification.
Feedback
Learning returns to Service, Method, Pattern, Canonical basis and queue.

Kinematics: creation, qualification, composition, activation, observation, transformation, asset conversion and feedback.

MECE ownership rules

Service owns: a bounded capability promise and its intended outcome contribution.
Method owns: the repeatable way of performing or analysing work.
Pattern owns: reusable structural regularity supported by evidence.
Canonical Library owns: authoritative reference state and promotion basis.
Work Object owns: the bounded execution instance, queue state and next action.
Benefit owns: measurable advantageous change for an identified beneficiary.
Asset owns: persistent, qualified and reusable value. Outputs are not Assets by default.

Reference-package assurance

Traceability: nine Canvas cells map to 27 HTML cells by stable unique trace IDs — SC-<P|S|A>-<FM|FL|EV>[-S|B|R]; no ID is reused across planes.
MECE: Service boundaries and ownership rules separate Service, Method, Pattern, Canonical, Work Object, Benefit and Asset.
Inversion: HOLD on duplicate scope, missing beneficiary, absent Method/Pattern basis, unsupported activation, false Benefit attribution or premature Asset claim.
A/B: comparisons must state decision question, hypotheses, evidence for/against, expected Benefit, Asset effect, learning and decision.
Source integrity: Odoo remains operational truth; Working Memory remains evidence truth; this page is a design projection.
