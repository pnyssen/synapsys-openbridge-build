Nine verbs applied

Orient

Identify the recurring problem, evidence set and candidate value.

Canonicalise

Resolve Pattern identity and the canonical references it depends on.

Structure

Bind recurrence, Contexts, Methods, evidence, Benefits and Asset effects.

Assure

Test repeatability, counterexamples, attribution and admission criteria.

Navigate

Find the applicable Pattern or Asset candidate by Context and purpose.

Compose

Combine admitted Patterns and qualified Assets into Services and Work Objects.

Activate

Use only admitted/authorised expressions; candidate status remains visible.

Transform

Revise or split Patterns when evidence shows overlap or variation.

Project

Display evidence, admission, maturity, reuse and qualification states.

Mesh integration

Entry

A signal or governed need enters with identity, Context and source.

Validation

Evidence, MECE, authority, PPV and readiness are tested.

Action

Only an authorised expression may change governed work.

Observation

Effects, exceptions and source receipts are recorded.

Asset conversion

Reusable value is proposed only after repeated evidence.

Feedback

Learning returns to the owning element and current Work Object.

Cross-element MECE ownership

Owns

Recurring structural pattern, admission evidence, Asset qualification, maturity and reuse.

Does not own

Method steps, canonical authority, Service scope, Benefit measurement, Work Object queue or runtime execution.

Integration contract

Every relationship names the owning element, referenced object, evidence route and authority state; shared relationships are explicit, never duplicate ownership.

Design-instance inventory

Enough instance identity and relationships are shown for design, integration and stress testing. Mutable operational fields, transactions, performance and runtime configuration remain in Odoo/N8N.
