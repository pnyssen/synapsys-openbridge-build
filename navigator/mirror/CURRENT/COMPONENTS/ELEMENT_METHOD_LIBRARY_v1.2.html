Nine verbs applied

Orient

Identify the problem class, Context and fitness criteria.

Canonicalise

Resolve Method identity, version and canonical basis.

Structure

Define inputs, steps, roles, outputs, controls and evidence.

Assure

Test repeatability, limitations, safety and differentiation from Patterns.

Navigate

Select the fit Method for a Service or Work Object.

Compose

Combine Methods without duplicating steps or controls.

Activate

Release an authorised Method instance into a Work Object.

Transform

Revise the Method from observation, exceptions and comparative tests.

Project

Show active, inactive, draft and held Methods with relationships.

Mesh integration

Entry

A signal or governed need enters with identity, Context and source.

Validation

Evidence, MECE, authority, PPV and readiness are tested.

Action

Only an authorised expression may change governed work.

Observation

Effects, exceptions and source receipts are recorded.

Asset conversion

Reusable value is proposed only after repeated evidence.

Feedback

Learning returns to the owning element and current Work Object.

Cross-element MECE ownership

Owns

Repeatable procedure, required inputs, steps, controls, outputs and fitness conditions.

Does not own

Pattern recurrence, canonical authority, Service offer, runtime state, Benefit claim or Asset qualification.

Integration contract

Every relationship names the owning element, referenced object, evidence route and authority state; shared relationships are explicit, never duplicate ownership.

Design-instance inventory

Enough instance identity and relationships are shown for design, integration and stress testing. Mutable operational fields, transactions, performance and runtime configuration remain in Odoo/N8N.
