Nine verbs applied

Orient

Establish current objective, queue position, Context and constraints.

Canonicalise

Resolve Work Object identity and source records.

Structure

Bind scope, owner, evidence, authority, risk and acceptance tests.

Assure

Test readiness, dependencies, STOP/HOLD and replay validity.

Navigate

Select the next valid queue item and return path.

Compose

Assemble Services, Methods, Patterns and agents required for the bounded move.

Activate

Release exactly one authorised next action.

Transform

Update the Work Object state from observed results.

Project

Show current queue, owner lanes, blockers and completed receipts.

Mesh integration

Entry

A signal or governed need enters with identity, Context and source.

Validation

Evidence, MECE, authority, PPV and readiness are tested.

Action

Only an authorised expression may change governed work.

Observation

Effects, exceptions and source receipts are recorded.

Asset conversion

Reusable value is proposed only after repeated evidence.

Feedback

Learning returns to the owning element and current Work Object.

Cross-element MECE ownership

Owns

Bounded objective, queue state, owner lane, authority, evidence, risk, next action and replay validity.

Does not own

Enterprise canon, Service identity, Method design, Benefit definition, Asset qualification or runtime execution.

Integration contract

Every relationship names the owning element, referenced object, evidence route and authority state; shared relationships are explicit, never duplicate ownership.

Design-instance inventory

Enough instance identity and relationships are shown for design, integration and stress testing. Mutable operational fields, transactions, performance and runtime configuration remain in Odoo/N8N.
