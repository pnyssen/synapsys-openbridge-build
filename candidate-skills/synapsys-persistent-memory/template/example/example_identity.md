# Example Collaborator Co — Persistent Memory (worked example v0.1)

This is a WORKED EXAMPLE, not a real organisation. It exists to prove
the two-file pattern is genuinely portable: this file validates against
the exact same, unmodified `validate_memory_files.py` used for the
SynapSys instance — no SynapSys-specific logic was added to make it
pass.

## Purpose (Board-ratified 2026-01-01)
Deliver repeatable precinct-capability outcomes for our clients.

## Operating discipline
Idea maturity ladder: Draft -> Piloted -> Standard (Example Collaborator
Co's own three-stage model — deliberately different wording from
SynapSys's FORM/FLOW/EVOLVE, to prove the pattern doesn't require
adopting SynapSys's specific vocabulary).
Evidence ladder: Claimed -> Demonstrated -> Audited — a separate axis
from maturity, same principle as SynapSys's Potential/Probable/Verified,
different labels.
Asset-declaration discipline: not yet defined for this organisation —
stated plainly rather than invented for the example.

## Standing rule
Never claim this organisation's state from memory alone. Re-fetch the
live delivery register fresh, every time, before making the claim.

## What this file is not
Not authority, not canon, not a substitute for the organisation's own
system of record or its equivalent of an always-loaded operational
file. If content needs to change often, it doesn't belong here — keep
it in deep storage and reference it, don't inline it.
